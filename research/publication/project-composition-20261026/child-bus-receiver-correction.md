# Correction: Child Bus uses FSubList, not FObjectList

This corrects the earlier `field-encoding-addendum.md` receiver interpretation, while retaining that original note, source revisions, authored passes and real-file observations. The earlier note mistakenly called the key at `1038fe6e2` FAttrObjectArray. The original bytes, already captured in `field-encoding-custody.json`, actually spell **FSubList**. This correction is material to candidate applicability.

`1031a0e1c` counts a field compatible with FAttrList. The later getter `1031a0ce8` specifically checks FSubList before advancing its index and retrieving a dictionary. Merely passing the general count check does not satisfy the member getter.

The compound dispatch table maps subtype5 to `1031abd10`: read signed32 count, create an FSubList object with primary table `104e46508`, and read each anonymous FAttributes dictionary by recursively calling `1031ab5b8`. Its type-check method `1031adf70` accepts FSubList, and with base search also FAttrList/CmObject/base-object names. The map for subtype201 remains a different counted typed20/deferred21 object list, table `104e46408`; its type-check method `1031addc8` accepts the distinct name at `1038fe6cc` and its base names, not FSubList. Fresh REA for both type-check methods and original-byte verification are retained in pass26/rea-pass26; `verification-list-types-01.json` covers all 97 functions/readbacks.

The decoder now represents these two list forms distinctly. Only subtype5 anonymous dictionaries satisfy Child Bus candidate traversal. A structurally valid subtype201 typed FAttributes list cannot manufacture child-bus candidates. Unsupported object-list member encodings/references still prevent complete attribute parsing. Named duplicate keys remain strict application policy; neither list is modeled by repeated named keys.

The actual private device-prefix extension registered the earlier MTrack v2 declarations and reached inline FAttributes in all five typed audio resources. Every one then stopped at subtype5 `InputFilter/Audio Input Arrangement`; a separate bounded private diagnostic supports subtype5 and numeric arrays2/3 and proceeds to subtype7 `InputFilter/audioComponent`. This remains unsupported in production at this milestone. Compound7's payload is not assumed to be a raw blob merely because it begins with a length. No complete real-template mixer candidate is claimed.

Numeric arrays2 and3 are bounded counted 64-bit values per branches `1031abc50` and `1031abcb0`. The decoder can consume and retain their enclosing original state but cannot promote an array to a scalar route or Volume. Authored controls reject oversized/truncated arrays and verify that scalar candidates remain absent. All input source bytes and historical reports are unchanged.
