# First source-stream CI and subsequent corrections

The first Windows application run, [40255436855](https://github.com/thatsmethen/rebase/actions/runs/40255436855), and component run, [40255436874](https://github.com/thatsmethen/rebase/actions/runs/40255436874), tested commit `328849cfbe4ad26b5c2d441cbc08d32ec8b0b0bd`. Both failed. No application ZIP or actual-window observation was produced. The existing preview.8 release remains available and unchanged.

`first-ci.json` preserves the exact job outcomes, test counts, failed case names and original artifact/log hashes. The Windows application passed 524 authored host checks before the native stream test stopped the build. In both native Windows configurations, lifecycle and rate-conversion tests passed while the new complete long-stream drain missed its existing deadline. All four shared Swift configurations rejected source-stream ticket preparation. The public macOS application suite executed 280 tests with 119 explicit skips and no failures. These narrower results do not accept the failed candidate.

Source inspection found that the native producer's condition-variable predicate accepted cancellation alone. Normal notifications for submitted input or available endpoint capacity therefore continued waiting until the timeout. The correction waits for the relevant source-window, EOF or endpoint-space condition, keeping cancellation, the bounded fallback, the original performance deadline, queue capacities, PCM locks and ABI unchanged. Local macOS Debug, Release and UBSan each passed all three native tests after the change; the 32,004,240-frame stream retains its exact original hash. `native-local-receipt.json`, `native-stream-release.json` and `native-tests.json` bind these observations to source hashes. Corrected Windows execution remains a separate acceptance requirement.

The macOS default-environment fixture failure was reproduced locally: its system temporary directory contained the `/var` alias, which the strict ancestor checks reject. Authored fixtures now use the checkout's ignored scratch directory by default. Windows traversal also used a POSIX-only root boundary; the correction recognizes an absolute local drive root and stops only after checking it. UNC, device and drive-relative namespaces are explicitly outside this source-stream custody contract. Canonical-path, directory and reparse-point checks remain unchanged. New tests check path syntax and traversal through the actual host filesystem root; native Windows confirmation remains required.

`filesystem-correction.json` binds the retained failing reproduction, 12 passing focused tests and the full default-environment suite: 133 executed, three explicit generator skips and zero failures. It also records the rebuilt production helper and unchanged prior helper hashes. Earlier unexplained failures are not retrospectively attributed to this correction.

These are authored implementation and instrument corrections. They are not new observations of proprietary playback or proof of full application parity. Original failed records remain unchanged in private custody; this publication contains reviewed derivatives and hashes, with no raw tickets, capabilities or local process traffic.
